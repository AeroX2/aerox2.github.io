Nullify

Product Engineer

March 2026–present

Rebuilding the frontend

I rebuilt Nullify’s frontend from the ground up with Vite and an atomic component architecture, now 470 components. I owned the architecture and built most of the features, and cut the compressed initial JS and CSS from 932 kB to 453 kB.

AI-generated code kept making the same mistakes, like adding new buttons instead of reusing existing ones. I defined ESLint rules for component dependency direction, colour tokens, and shared primitives so those mistakes fail the lint.

For visual regressions, Playwright screenshots selected Storybook components in light and dark themes on the PR and its base, ImageMagick diffs them, and the differences are posted on the pull request. End-to-end tests cover the main UI flows.

Backend startup time

Removing OpenAPI reflection from Go startup cut Lambda initialisation from 1.9 s to 1.1 s in a development deployment. Keeping a Python process alive across warm invocations cut Python startup overhead from 9.7 s to 50 ms.

Tracking down broken links in Next.js

Links stopped responding after a Next.js upgrade. I spent several days stepping through JavaScript in the browser and comparing the execution with the framework source to understand the failure. I found the cause and wrote a patch.

Prefetching in a static export was receiving HTML where it expected React Server Component data. By the time I had a patch, someone else had already addressed the same bug.

Software Engineer

Previews for Magic Design

Magic Design needed to preview generated text and selected photos in preset layouts outside the editor. Rendering each design as a full DOM tree slowed the page down. I searched Canva’s codebase for another approach and found the editor’s canvas renderer.

I adapted it to produce image previews and agreed the reuse with the editor team. By my estimate that saved months compared with building a separate renderer.
